# API Worker — أساس الهوية فقط

هذا مجلد خدمة Cloudflare Workers منفصل عن خادم Shelf/SQLite القديم. أُنشئ كطبقة ربط أولية بين تطبيق Flutter وFirebase Authentication/Firestore، وليس كإصدار مصدر مالي مركزي.

## ما يعمل في هذا الأساس

- `GET /health`: فحص صحة عام لا يكشف إعدادات أو أسرارًا.
- `GET /api/v1/me`: يتحقق من Firebase ID token بتوقيع RS256 ومطالبات المشروع (`iss` و`aud` ووقت الصلاحية و`sub`) والبريد المتحقق، ثم يعيد قراءة عضوية UID والمحطة من Firestore.
- يرفض العضوية الغائبة أو المعطلة، الدور غير المعروف، المحطة المعطلة، ومجال المستفيد/الشريك/العامل غير المحدد. لا يوجد fallback إلى محطة `1`.
- يقيّد CORS بأصل صريح في `ALLOWED_ORIGINS` عند استخدام Web.
- **جميع مسارات `/api/v1/finance/*` ترجع 503 عمدًا ولا تنفذ أي كتابة.** هذا حاجز أمان حتى تكتمل مطابقة العمليات المالية واختبارها.

## الإعداد

المتطلبات: Node.js 22 أو أحدث و`npm` أو `pnpm`.

```sh
cd server/worker-api
npm ci
npm run check
npm test
npm run dev
```

تحتاج بيئة التطوير المحلية إلى متغيرين، ويُحفظان خارج Git:

- `FIREBASE_PROJECT_ID`: معرّف مشروع Firebase الفعلي.
- `FIREBASE_SERVICE_ACCOUNT_JSON`: JSON لحساب خدمة مخصص، يُخزن في Secret وليس في Flutter أو Git.
- `ALLOWED_ORIGINS`: اختياري؛ قائمة مفصولة بفواصل لأصول الويب المسموح بها.

في الإنتاج، يُضبط مفتاح حساب الخدمة كـCloudflare Worker Secret من لوحة Cloudflare أو الأمر التفاعلي المناسب، ولا يُضاف إلى `wrangler.toml` أو المستودع. يجب أن يكون حساب الخدمة مخصصًا للخدمة وبأقل صلاحية IAM لازمة، دون Owner/Editor. لا يستخدم هذا الكود Firestore Admin SDK؛ بل يرسل طلبات REST موقعة بحساب الخدمة. وثائق Firebase تنبه إلى أن وصول مكتبات الخادم يعتمد على IAM ويتجاوز Firestore Security Rules، لذا يفرض هذا الـAPI تحقق العضوية والمحطة بنفسه.

عند اكتشاف تغيّر قيمة سر حساب الخدمة، يمسح العميل مخزن بيانات الحساب ورمز OAuth ويستخدم السر الجديد في الطلبات اللاحقة؛ أما الطلب الذي بدأ قبل التدوير فقد ينتهي بالاعتماد السابق. راقب النشر والتدوير، ولا تُبقِ المفتاح القديم صالحًا بعد التحقق من انتقال الخدمة. يتحقق Firebase verifier من أن `auth_time` رقم زمني معقول وغير مستقبلي، لكنه لا يفرض إعادة مصادقة حديثة؛ أي عملية حساسة مستقبلًا يجب أن تضيف شرط حداثة مناسبًا.

ملف `wrangler.toml` يحدد حد CPU قدره 10 ms كي لا يخفي تجاوز حدود الخطة المجانية. لم يتم نشر Worker أو إنشاء أسرار أو تعديل إعداد Cloudflare/Firebase من هذا المستودع. لا تنشئ سر حساب الخدمة ولا تنشر الخدمة قبل مراجعة صلاحياته ونجاح الاختبارات.

## غير جاهز للاستخدام المالي

ما زالت قاعدة SQLite المحلية مصدر العمليات الحالي، ولا توجد في هذا Worker مسارات كتابة مالية أو مخطط دفتر أستاذ مركزي. توثيق الخطة وبوابات التحقق: [`docs/PRODUCTION_READINESS.md`](../../docs/PRODUCTION_READINESS.md). يجب إبقاء التطبيق على المسار المحلي إلى أن تُنفذ جميع عمليات الدفع والمصروف والتحويل والري والإلغاء والتسويات، وتنجح اختبارات التكافؤ والعزل والتزامن والاستعادة. ظهور `/health` بنجاح لا يعني جاهزية مالية أو اعتمادًا إنتاجيًا.
