## End-to-end mapping

| Layer | Behavior |
| --- | --- |
| Existing `AccountingService.createWorkerAccrualBatch` | Retains the existing offline-first one-transaction posting and balanced per-worker `5000` debit / `2100.W*` credit; validates station, fixed/active worker, period and positive amounts; tags rows `fixed_salary_batch`. Posting date may differ from entitlement period, preserving prior behavior. |
| Local metadata | Existing notes retain their established key/label and append `P3C_RANGE:YYYY-MM-DD:YYYY-MM-DD` with **exclusive** end; no new database migration/table. |
| `AppDatabase.transaction` | Existing `captureSyncRecordIds` mechanism retains **only first worker** as Outbox root, while ensuring stable UUIDs for every captured worker movement and financial child. |
| `BusinessSyncPayload.prepare` | Parses the original period/label and exclusive date range; includes `_p3c_batch.members` with each worker movement UUID, reference to worker UUID and integer amount; includes one journal UUID and two journal-line UUIDs per worker plus an empty cashbox identity list. |
| `_applySyncWorkerFixedSalaryBatch` in Shelf | Checks role/station and root/member UUIDs, no cross-station workers, no repeated worker, positive amounts, dates/range, period closures, period overlap/legacy duplicate, root/manifest consistency. **Computes the journal itself** for each member, not from client-supplied journal totals. |
| Existing Shelf event SAVEPOINT | Every member movement, every GL journal line, event log, version update and associated projection are committed or rolled back together; failure during second member posting must remove the first. |
| Inbox | Publishes N-1 non-root worker movements **to origin and peers**, along with all server-created journal entries and lines; peers receive root from original event log. UUID links, not numeric local IDs, reconcile already-existing origin rows. |
| Cashbox | No movement; the required `cashboxes` manifest is empty. |

### Wire command (shape, not user credentials)

```json
{
  "entity_type": "worker_transactions",
  "entity_key": "worker_transactions:<root-uuid>",
  "operation": "create",
  "base_version": 0,
  "payload": {
    "_global_id": "<root-uuid>",
    "type": "accrual",
    "reference_type": "fixed_salary_batch",
    "date": "2090-05-05T23:59:59.000",
    "amount": 1100,
    "_global_refs": {
      "worker_id": {"table": "workers", "global_id": "<worker-a-uuid>"}
    },
    "_p3c_batch": {
      "period_key": "P3C-2090-04",
      "period_label": "April 2090",
      "period_from": "2090-04-01",
      "period_end_exclusive": "2090-05-01",
      "members": [
        {"global_id": "<root-uuid>", "worker_ref": {"table": "workers", "global_id": "<worker-a-uuid>"}, "amount": 1100},
        {"global_id": "<second-uuid>", "worker_ref": {"table": "workers", "global_id": "<worker-b-uuid>"}, "amount": 2200}
      ]
    },
    "_derived_global_ids": {
      "journal_entries": ["<entry-a-uuid>", "<entry-b-uuid>"],
      "journal_lines": ["<line-a1-uuid>", "<line-a2-uuid>", "<line-b1-uuid>", "<line-b2-uuid>"],
      "cashboxes": []
    }
  }
}
```

The transport UUID placeholders above are documentary labels; actual commands use UUIDv4 generated by the identity service. Neither client ledger account IDs nor client financial line totals are trusted.
