# سعر الدقيقة الخاص في التقارير — نقل انتقائي إلى فرع Firebase

- المصدر: `feature/work-price-difference`، وفق `docs/WORK_PRICE_DIFFERENCE_SPEC_2026-11-05.md`.
- الوجهة: `feature/firebase-station-foundation`، دون تعديل `main`.
- نطاق النقل: اختيار مدير `work_price_report_display_special_rate` وسعر `work_minute_rate`، عرض تقارير الفواتير والمديونيات وPDF، مع لقطة `work_minute_rate_snapshot` للسقاية.
- **لا تُنقل** ميزة تغيير قيمة فاتورة السقاية عند الإدخال أو تغيير نصيب العمال والشركاء. المبالغ المحاسبية وسندات القبض والقيود كما هي.
- الإصدار المحلي SQLite 32: إضافة العمود عند إنشاء جديد أو ترقية، وتثبيت سعر الإعداد الحالي للسقايات التاريخية التي لا تحمل سعراً؛ القيمة ليست بالضرورة السعر الحقيقي في تاريخ السقاية. لا تغيير في القيد المالي.
- الخادم يضيف العمود عند التهيئة ويقبل لقطة سعر العرض ضمن أمر مزامنة السقاية المقبول ويعيدها للأجهزة في الإسقاطات، دون إعادة احتساب فاتورة مالية.
- عند غياب سعر خاص محفوظ، يعرض التقرير السعر العام. ينبغي ضبط السعر قبل إنشاء سقايات جديدة.
- اختبار تغيير الإعداد بعد حفظ السقاية، وكذلك الترقيات القديمة، مطلوب للتحقق التاريخي.
- إعدادات واجهة العرض محفوظة محلياً لكل جهاز حالياً، وليست سياسة محطة متزامنة تلقائياً؛ توحيد الإعداد على جميع الأجهزة يحتاج آلية تهيئة معتمدة مستقبلاً.
- لا استعادة تلقائية لقاعدة `saqia_special_minute_rate_120_v24.db`؛ فهي تحتوي بيانات حقيقية ولا يجوز استبدال قاعدة العميل بها دون نسخة احتياطية وإذن.
- حالة التحقق: لا يُعلن نجاح الاختبارات أو APK قبل الاطلاع على CI لهذا الالتزام.

## ملحق إصلاح بعد النقل

- إضافة اختبارات لحساب سعر الدقيقة في الحالات 1/30/60/90 دقيقة مع المقارنة بالأساس العام.
