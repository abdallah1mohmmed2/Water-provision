# تسليم الديزل من الشخص إلى المنظومة

الزر «إضافة تسليم ديزل» في قسم الديزل فقط. يختار المستخدم مستفيدًا أو عاملًا أو شريكًا من المحطة، واللترات والتاريخ والملاحظات، ويعاين صافي «له/عليه» قبل الحفظ وبعده.

اتجاه التسليم وارد إلى المنظومة: يسدّد اللترات السالبة السابقة أولًا، والفائض رصيد موجب للشخص. مثال: عليه20 ويسلم15 فيبقى عليه5؛ له10 ويسلم15 يصبح له25. السقاية تخصم استهلاكها الفعلي، حتى يصبح الرصيد سالبًا عند العجز. لا شرط مخزون؛ وارد الشخص يزيد المخزون حتى لو كان سالبًا. لا قيمة مالية ولا صندوق ولا قيد مخزون نقدي.

التخزين: ترقية34 تضيف worker_id/partner_id وparty_receipt وعلامة request_id الفريدة. تُستخدم kind=receipt مع party_receipt=1 لتبقى قيود CHECK التاريخية سليمة، دون إعادة بناء أو حذف جدول الوقود. عمود الطرف واحد فقط. لا تعديل للأرقام التاريخية أو أسعارها.

صافي اللترات: افتتاحي + مرحل + تسليمات قديمة + وارد الشخص الجديد + السلف اليدوية المتاحة - استهلاك السقايات. السلفة الآلية المرتبطة بسقاية علامة لكمية العجز، ولا تضاف إلى صافي الرصيد كي لا تمحو الدين؛ يُحدّ عجز السقاية التالية بكمية استهلاكها، فلا تتحول السلفة القديمة إلى سلفة مكررة. السلف اليدوية القديمة تحتفظ بسياسة رصيدها المتاح ولا يعاد تحويل سنداتها المالية التاريخية. العامل والشريك يُربطان باستهلاكهما عبر صاحب السقاية، وليس العامل المشغّل.

الإلغاء: حركة receipt سالبة بنفس علامة الطرف وreversal_of للأصل، سبب إلزامي وتدقيق، دون حذف الأصل أو اشتراط مخزون. ترفض محاولة إلغاء ثانية أو إلغاء حركة عكسية. تعديل الملاحظات لا يعدل كمية/طرف الحركة.

المزامنة: root diesel_movements نفسه، مع مراجع UUID للعامل والشريك والمستفيد والعكس. الخادم يتحقق من محطة JWT والدور والديزل والكمية الصفرية ماليًا وإغلاق الفترة، ويمنع التكرار والعكس المخالف/المكرر. Inbox يطبق المراجع حسب FK دون إنشاء قيد أو أثر ثانٍ. لا تفعيل جديد للمزامنة أو نشر خادم ضمن هذه المهمة.

الاختبار والقبول النهائي يتبعان §44 من سجل العمل. لا ادعاء بفحص هاتف المستخدم فعليًا.
