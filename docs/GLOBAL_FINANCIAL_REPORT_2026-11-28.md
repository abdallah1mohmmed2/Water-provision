# التقرير المالي العام للمنظومة — 2026-11-28

## الهدف
تقرير مستقل عن التقارير الحالية، يجمع السقايات المنفذة والقبوضات والمصروفات وأرصدة المستفيدين وحصص الشركاء في جميع أنواع المحطات: شمسي، ديزل، ونوع ثالث (شمسي/ديزل).

## قواعد الحساب
- **إيراد السقايات:** مجموع `total_amount` للسقايات غير الملغاة التي تاريخها داخل الفترة. لا تضاف الديون القديمة إلى إيراد الفترة.
- **القبوضات:** مجموع الدفعات المرحّلة للمستفيدين بتاريخ القبض داخل الفترة؛ يشمل تحصيل الديون السابقة.
- **المصروفات:** المصروفات المرحّلة للمحطة داخل الفترة، مع استبعاد المصروفات المرتبطة مباشرة بشريك أو عامل، وفق تصنيف تقرير المالية الشهري الحالي.
- **الصافي القابل للتوزيع:** القبوضات ناقص مصروفات المحطة. إذا كان سالبًا يظهر العجز، وتكون حصص الشركاء صفرًا.
- **أرصدة المستفيدين:** رصيد كل مستفيد عند نهاية الفترة (افتتاحي + مرحّل + مديونية سابقة + سقايات حتى نهاية الفترة + سلف ديزل يدوية - دفعات حتى نهاية الفترة - تسليم الديزل فقط عندما يكون رصيدًا ماليًا). إجمالي الرصيد المستحق يجمع الأرصدة الموجبة فقط؛ رصيد «له» يظهر منفصلًا على بطاقة الشخص.
- **حصص الشركاء:** تستخدم `AccountingCalculations.partnerDistributionAmounts` وقواعد ملكية النسبة/الحصص الحالية. هي حسبة فقط ولا تنشئ صرفًا أو قيدًا.

## القبض من مديونية سابقة
تقديري read-only: يُحسب الدين المستحق لكل مستفيد قبل تاريخ بداية التقرير من الأرصدة الافتتاحية/المرحّلة والمديونيات اليدوية والسقايات وسلف الديزل والدفعات السابقة (وتسليم الديزل المالي إن كان مفعّلًا)، ثم يُحدّ المقبوض في الفترة بقدر ذلك الدين لكل مستفيد. لا تعتمد النتيجة على تخمين جماعي قد ينسب قبض مستفيد بلا دين إلى ديون الآخرين. لا يوجد تخصيص أو تعديل لأي دفعة.

## الشاشة وPDF
- قائمة التقارير: «التقرير المالي العام للمنظومة».
- تاريخ من/إلى مع «كل الفترة».
- ست بطاقات ملخص، جدول المستفيدين، ثم جدول الشركاء.
- PDF رسمي واحد يحتوي جدول المستفيدين وجدول الشركاء في نفس الملف، مع نفس snapshot الحسابات المستخدمة بالشاشة.

## ملفات التنفيذ
- `lib/features/global_financial_report.dart`: SQL read-only، حسابات، شاشة، وPDF.
- `lib/features/app.dart`: إدراج التقرير في قائمة التقارير وربط فتح الشاشة والطباعة.
- `lib/services/report_service.dart`: اسم التقرير وأعمدة العرض.
- `lib/data/repositories/repositories.dart`: تسجيل مفتاح التقرير في موجه التقارير.
- `lib/services/official_report_template.dart`: دعم قسم جدول إضافي داخل نفس PDF (اختياري، لا يغير التقارير الحالية ما لم تستخدمه).
- `test/global_financial_report_math_test.dart`: اختبارات حساب صافي التوزيع، تجميع المستحقات الموجبة، وتقدير القبض من دين سابق لكل طرف.

## حدود التحقق
لا توجد هنا بيئة Flutter محلية لتشغيل `flutter analyze` أو `flutter test` أو بناء APK. GitHub Actions على الفرع هو التحقق التنفيذي؛ يجب انتظار نتائج Analyze وBuild قبل إعلان الاكتمال النهائي. الاختبارات الحسابية لا تغني عن اختبار SQL على قاعدة SQLite فعلية.

## سيناريوهات الاختبار المحاسبي المطلوبة في CI/المراجعة
- دين سابق فقط مع قبض دون سقايات جديدة: لا يزيد إيراد الفترة، ويزيد القبض والصافي.
- سقاية داخل الفترة دون قبض: الإيراد يزيد، القبض لا يزيد، ويظل الرصيد المستحق.
- قبض جزئي/كامل للدين القديم: تقدير القبض القديم لا يتجاوز الدين القديم لكل مستفيد.
- مصروفات فترة: تقلل صافي التوزيع.
- لا سقايات مع قبض دين سابق: القبض يدخل التوزيع، الإيراد يظل صفرًا.
- الصافي السالب: يظهر عجز ولا توزع حصص سالبة.
- الأنواع الثلاثة: التقرير لا يفلتر على نوع النظام الحالي.
- تحديد فترة مقابل «كل الفترة»: لا تعدّل السجلات أو الأرصدة.
- PDF والشاشة يستخدمان نفس بيانات التقرير؛ حصص الشركاء ليست عملية صرف.
