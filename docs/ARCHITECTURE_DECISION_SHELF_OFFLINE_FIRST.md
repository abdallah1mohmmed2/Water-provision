# القرار المعماري — Shelf Offline-First لمحطة «منظومة»

- الحالة: معتمد للتنفيذ المرحلي
- الفرع: `feature/firebase-station-foundation`
- النطاق: التطبيقات الأربعة (الإدارة، المستفيد، العامل، الشريك)
- قاعدة السلامة: لا تعديل أو دمج إلى `main` دون موافقة صريحة.

## 1. القرار

اعتماد **Shelf API + JWT** كنظام الدخول والواجهات الخلفية الموحد، وعدم استخدام Firebase Authentication أو Firebase Custom Tokens.

تبقى SQLite قاعدة التشغيل المحلية للعمليات اليومية والمالية. لا تُنقل القيود أو الأرصدة إلى Firestore، ولا تُفعّل مزامنة قبل اكتمال عقد API واختبارات منع التكرار والتعارض.

## 2. شكل النظام المستهدف

```text
تطبيق الإدارة ───────┐
تطبيق المستفيد ─────┤
تطبيق العامل ───────┼── HTTPS / Local Network ── Shelf API
تطبيق الشريك ───────┘                              │
                                                   ├── JWT + صلاحيات
                                                   ├── قواعد العمل والتحقق
                                                   └── SQLite محطة «منظومة»
                                                        │
                                                        └── Outbox / Sync (مرحلة لاحقة)
                                                               │
                                                               └── Cloud API + PostgreSQL
```

### التشغيل المحلي

- يعمل Shelf على جهاز خادم المحطة داخل الشبكة المحلية، وتكون قاعدة SQLite الموجودة على هذا الجهاز هي قاعدة المحطة المشتركة.
- تتصل تطبيقات الإدارة والمستفيد والعامل والشريك بالخادم المحلي عند توفر شبكة المحطة؛ انقطاع الإنترنت الخارجي لا يوقف اتصال LAN.
- تحتفظ التطبيقات على الهواتف بقاعدة SQLite محلية للقراءة المخزنة والطلبات المعلقة، ولا تعتبر أرصدتها المحلية المعروضة نهائية قبل اعتماد الخادم.
- إذا تعذر الوصول إلى خادم المحطة، تُحفظ الأوامر المسموح بها في Outbox محلي مع UUID وحالة «بانتظار المزامنة»؛ لا تُعاد المحاولة بطريقة قد تكرر قيداً مالياً.
- لا يفتح الخادم على جميع واجهات الشبكة افتراضياً؛ يلزم ضبط عنوان الربط صراحةً عند الحاجة.

### الوصول عن بُعد

- يكون الاتصال عبر HTTPS فقط، خلف Reverse Proxy أو بوابة آمنة.
- لا يُعرض منفذ Shelf مباشرةً على الإنترنت دون TLS وجدار حماية ومراقبة.
- عند التوسع إلى عدة محطات أو اتصالات متزامنة، يكون PostgreSQL هو مخزن الخادم المركزي المقترح.
- لا يوجد في المستودع حتى الآن دليل على نشر الخادم أو تجهيز PostgreSQL adapter؛ هذا عمل لاحق وليس ميزة جاهزة.

## 3. المصادقة والصلاحيات

- المدير/المحاسب/التشغيل: تسجيل الدخول عبر `app_users` في Shelf، ثم JWT.
- المستفيد: يستمر مسار المستفيد الحالي في Shelf إلى أن يُراجع ويُوحّد مع سياسة الجلسات.
- العامل والشريك: تُضاف حساباتهما وتطبيقاتهما كأنواع هوية وصلاحيات مستقلة في Shelf، لا كصلاحيات يقررها العميل.
- يحدد الخادم `userId` و`stationId` و`role`؛ لا يقبل هذه القيم من جسم الطلب لتحديد هوية المستخدم.
- JWT قصير العمر، مع Refresh Token قابل للإلغاء والتدوير في مرحلة إدارة الجلسات.
- كلمات المرور يجب أن تنتقل من SHA-256 غير المملح إلى Argon2id أو خوارزمية تخزين كلمات مرور معتمدة، عبر ترحيل متوافق لا يكسر الحسابات القائمة.
- يجب إضافة تحديد محاولات تسجيل الدخول، وإلغاء الجلسات، وسجل تدقيق قبل النشر العام.

## 4. قواعد البيانات والمزامنة

### الآن

- لا تغيير على مخطط SQLite المالي ولا على البيانات القائمة ضمن هذه المرحلة.
- SQLite هي المرجع الوحيد للقيود المالية داخل المحطة.
- تطبيقات الأجهزة الأخرى يمكن أن تحتفظ بذاكرة محلية/قائمة أعمال معلقة، لكنها لا تصبح مرجعاً مالياً مستقلاً.

### لاحقاً — لا تفعّل قبل الاختبار

يلزم تصميم Outbox/Inbox موثوق يتضمن على الأقل:

1. UUID ثابتاً لكل عملية، لا يتغير عند إعادة المحاولة.
2. Idempotency Key فريداً على الخادم لمنع تكرار السقاية أو الدفعة.
3. رقم تسلسلي/نسخة للسجل مع سياسة تعارض واضحة.
4. حفظ العملية والحدث في معاملة واحدة.
5. حالات واضحة: pending, in_flight, synced, conflict, failed.
6. إعادة المحاولة دون فقدان البيانات أو مضاعفة الأثر المحاسبي.
7. اختبارات انقطاع الاتصال، وإعادة الإرسال، وتعارض تعديل السجل، واستعادة النسخ الاحتياطية.

**ممنوع** مزامنة الأرصدة أو القيود كقيم قابلة للكتابة من العميل. تُرسل أوامر أعمال مصادق عليها، ويعيد الخادم احتساب الأثر المحاسبي داخل معاملة.

## 5. الفرق بين الهدف والوضع الحالي

البنية أعلاه هي الهدف المعتمد وليست مكتملة الربط بعد. الفحص أثبت أن تطبيق Flutter ما زال يفتح قاعدة SQLite خاصة به عبر `AppDatabase`، بينما عملية Shelf تفتح ملف SQLite عبر `SAQIA_DB` بشكل مستقل. لم يثبت أن التطبيق والخادم يقرآن ويكتبان إلى ملف قاعدة واحد أو أن جميع الشاشات تستخدم API الموحد.

لذلك لا يجوز افتراض أن التطبيقات الأربعة أصبحت متصلة بقاعدة محطة مشتركة بمجرد وجود Shelf API. يلزم تنفيذ انتقال تدريجي لكل ميزة: قراءة عبر API، ثم كتابة عبر أوامر أعمال، ثم تخزين محلي/Outbox عند الانقطاع، ثم مزامنة واختبارات مطابقة الأرصدة. يجب الحفاظ على SQLite الحالية ونسخها الاحتياطية أثناء الانتقال وعدم حذفها أو استبدالها تلقائياً.

## 6. نتائج فحص الكود الحالي

- يوجد بالفعل Shelf Router ومسارات دخول إدارية ومستخدم مستفيد، ويصدر الخادم JWT.
- لا يوجد مسار `/api/v1/sync` في Router الحالي، بينما `SyncService` يرسل طلباً إلى `/sync` ويضيف `ApiClient` بادئة `/api/v1`.
- جدول `sync_queue` الحالي لا يوفر UUID ثابتاً أو Idempotency Key أو معالجة تعارض مكتملة.
- بعض استعلامات الخادم التي تمت مراجعتها لا تتضمن تصفية `station_id`؛ لذلك لا نعلن جاهزية تعدد المحطات أو نشر متعدد المستأجرين قبل تدقيق كل المسارات.
- تخزين كلمة المرور الحالي يعتمد SHA-256 مباشرةً، ويحتاج ترحيلاً آمناً إلى خوارزمية مخصصة لكلمات المرور.
- لا يوجد دليل داخل المستودع على إعداد نشر فعلي للخادم أو إعداد TLS/Reverse Proxy أو PostgreSQL adapter.
- إعداد Firebase السابق لا يعني أن Firebase Authentication أو Firestore فُعّلا. تبقى قواعد Firestore deny-all، ولا تدخل Firebase في تسجيل الدخول أو نقل البيانات ضمن القرار الحالي.

## 7. ما تغير في هذه المرحلة

- أضيفت `server/lib/server_config.dart` للتحقق من إعدادات التشغيل.
- أصبح تشغيل الخادم يرفض البدء إذا لم يُمرر `SAQIA_JWT_SECRET` بطول لا يقل عن 32 بايت UTF-8، ويرفض السر الافتراضي المعروف.
- أصبح عنوان الربط الافتراضي `127.0.0.1` بدلاً من فتح كل واجهات الشبكة تلقائياً. يمكن ضبط `SAQIA_BIND_ADDRESS=0.0.0.0` عند إعداد الشبكة المحلية أو بيئة استضافة محمية.
- أضيف تحقق من صحة المنفذ وعنوان الربط.
- أصبحت Middleware الخاصة بمسارات الإدارة تشترط JWT من نوع `admin` مع `userId` و`stationId` موجبين؛ وأزيل الرجوع الصامت إلى المحطة رقم 1 عند غياب claim.
- أضيفت اختبارات Dart لإعدادات الخادم، وأضيف تشغيلها إلى CI.

## 8. متغيرات تشغيل الخادم

| المتغير | المطلوب | الافتراضي |
|---|---|---|
| `SAQIA_JWT_SECRET` | إلزامي، عشوائي، 32 بايت على الأقل | لا يوجد |
| `SAQIA_DB` | مسار ملف SQLite | `../saqia_station_v2.db` |
| `SAQIA_BIND_ADDRESS` | عنوان IP للربط | `127.0.0.1` |
| `PORT` | منفذ من 1 إلى 65535 | `8080` |

مثال إعداد محلي (لا تستخدم النص التجريبي التالي كسِر إنتاج):

```bash
export SAQIA_JWT_SECRET="$(openssl rand -base64 48)"
export SAQIA_DB="/absolute/path/to/saqia_station_v2.db"
export SAQIA_BIND_ADDRESS="127.0.0.1"
export PORT="8080"
dart run bin_server.dart
```

للسماح لأجهزة الشبكة المحلية بالوصول، اضبط `SAQIA_BIND_ADDRESS=0.0.0.0` مع جدار حماية يسمح فقط بشبكة المحطة. الوصول عبر الإنترنت يجب أن يمر عبر HTTPS gateway ولا يكون عبر منفذ Shelf المكشوف مباشرة.
