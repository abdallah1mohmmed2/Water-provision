# تفعيل الدخول عبر Firebase Authentication فقط

الفرع المستهدف: `feature/firebase-station-foundation`. المصدر هو `android/app/google-services.json` عبر `StationFirebaseConfig` ومعاملات البناء القائمة؛ لا يُستخدم ملف `lib/firebase_options.dart` التاريخي الخاص بمشروع آخر. غياب التهيئة أو اختلاف المشروع يحجب Android بدل الرجوع إلى دخول محلي مفتوح.

هذه المرحلة تضيف بوابة تفعيل لتطبيق Android أمام جميع شاشات التطبيق، مع إبقاء قاعدة SQLite المحلية والصلاحيات والقفل المحلي الحاليين. لا تضيف Firestore أو مزامنة أو تغييرات إلى الخادم.

## إعداد مسؤول المشروع

1. افتح مشروع Firebase الحالي `manzoma-ststion` ثم Authentication > Sign-in method.
2. فعّل Email/Password (البريد وكلمة المرور).
3. من Users > Add user أنشئ حسابًا لكل مستخدم تريد التحكم فيه بصورة مستقلة. لا تشارك الحساب نفسه بين مستخدمين تريد إيقاف أحدهم وحده.
4. ثبّت نسخة Android المبنية من هذا الفرع على الأجهزة وسجل الدخول بالحساب المخصص. لا تُحدّث النسخ القديمة نفسها عن بعد؛ لا بد من تثبيت التحديث.
5. للإيقاف اختر المستخدم ثم Disable account. ولإعادة السماح اختر Enable account وسجل الدخول مجددًا.

لا توجد شاشة تسجيل حساب ذاتي في التطبيق. Firebase Auth يسمح بإنشاء حسابات عبر واجهته العامة إذا كان موفر البريد مفعّلًا؛ عدم عرض زر التسجيل ليس قائمة سماح أمنية ضد العملاء المعدلين. إن كان مطلوبًا منع إنشاء الحسابات خارج التطبيق أيضًا، يلزم لاحقًا ضبط سياسة هوية/قائمة سماح موثوقة على الخادم. لا تضع مفتاح حساب خدمة أو صلاحيات Admin داخل APK.

## سياسة الاتصال والإيقاف

- الحساب المحفوظ لا يمنح الدخول حتى ينجح `reload` وتحديث الرمز من الشبكة.
- التحقق عند البدء والعودة للمقدمة، وكل 30 ثانية أثناء الاستخدام.
- تعطيل الحساب من لوحة Firebase لا يطلق حدث المصادقة وحده؛ لهذا يُعاد تحميله صراحة.
- عند فشل الاتصال يُحجب استخدام الواجهة دون حذف البيانات أو النماذج المحلية. لا توجد مهلة استخدام طويلة بلا اتصال. قد يبقى الدخول صالحًا إلى الفحص التالي، وتستغرق مهلة الطلبين المتتاليين حتى 24 ثانية؛ لذلك الإيقاف ليس لحظيًا.
- إغلاق جميع المستخدمين: تعطيل حساباتهم جميعًا. إغلاق مستخدم واحد: تعطيل حسابه وحده.
- الحساب هنا تصريح تشغيل للجهاز، ولا يغير دور المدير أو العامل أو الشريك المحلي، ولا يعزل البيانات بحسب حساب Firebase. تبديل حساب التفعيل لا يبدل قاعدة الجهاز.
- القفل يحجب الواجهة ولا يتراجع عن عملية قاعدة بيانات بدأت قبل الحجب، ولا يمحو بيانات الجهاز. ليس إدارة أجهزة عن بعد أو حماية ضد تعديل APK.

## التحقق قبل التوزيع

شغّل `flutter pub get` ثم `flutter analyze` واختبارات البوابة والمحاسبة، وابنِ APK. تحقق على هاتف فعلي من تسجيل الدخول، تعطيل الحساب أثناء فتح صفحة فرعية أو حوار، قطع الشبكة، إغلاق التطبيق وفتحه، وإعادة تمكين الحساب. تفعيل الموفر والحسابات والتحقق الحقيقي من Firebase يحتاج وصول مالك المشروع للوحة Firebase؛ ملفات الإعداد وحدها لا تثبت أن الموفر مفعّل.
